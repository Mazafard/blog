این شروع شد مثل هر روز دیگه‌ای. من دارم یک مخزن GitHub از دوستم رو بررسی می‌کنم که ناگهان یک بلاک بزرگ و خواندنی نیست از متن مقابول نظر من رفت. این داخل یک فایل Python نشسته بود، اما متغیرها فقط حروف‌آلود بودند. حس امنیت سایبری‌ام یک‌باره فعال شد—این کد ته‌پنهان‌شده‌ی خطرناک بود.

چیزی که در آن لحظه نمی‌دونستم اینه که من هم‌زمان یک حمله‌ی بزرگ و بسیار پیچیده‌ی زنجیره تامین رو کشف کردم که صدها مخزن در تمام GitHub رو آلوده کرده بود.

اینجا داستان اینه که چطور من اون رو پیدا کردم، براش کد نویسی برعکس کردم، و تو چطور می‌تونی مخازن خودت رو محافظت کنی.

## قطعه‌ی مریب

کد که من پیدا کردم اینطوری بود. این یک تکنیک کلاسیکی از ته‌پنهان‌کاری: پنهان کردن قصد واقعی اسکریپت پشت لایه‌های تودرتوی کد بندی و اجرای پویا.

```python
# -*- coding: utf-8 -*-
aqgqzxkfjzbdnhz = __import__('base64')
wogyjaaijwqbpxe = __import__('zlib')
idzextbcjbgkdih = 134
qyrrhmmwrhaknyf = lambda dfhulxliqohxamy, osatiehltgdbqxk: bytes([wtqiceobrebqsxl ^ idzextbcjbgkdih for wtqiceobrebqsxl in dfhulxliqohxamy])
lzcdrtfxyqiplpd = 'eNq9W19z3MaRTy......SN' # رشته‌ی base64 بزرگ کوتاه‌شده
runzmcxgusiurqv = wogyjaaijwqbpxe.decompress(aqgqzxkfjzbdnhz.b64decode(lzcdrtfxyqiplpd))
ycqljtcxxkyiplo = qyrrhmmwrhaknyf(runzmcxgusiurqv, idzextbcjbgkdih)
exec(compile(ycqljtcxxkyiplo, '<>', 'exec'))
```

با نگاه کردن سه خط آخری، جریان اجرا واضح بود:
1. رمزگشایی از Base64.
2. خارج‌کردن فشردگی با استفاده از Zlib.
3. رمزگشایی با استفاده از عملیات XOR (با کلید `134`).
4. اجرای بار‌گذاری خطرناک مستقیم در حافظه‌ی استفاده تابع بسیار خطرناک `exec()`.

## شکستن کد

ابتدا سعی کردم بار‌گذاری رو دستی رمزگشایی کنم، اما کار با رشته‌ی بزرگ و عملیات‌های تودرتو خسته‌کننده می‌شد. پس یک دستیار هوش‌مصنوعی (Claude) رو در محیط جدا‌گانه‌ای نشاندم و ازش خواستم یک "ته‌پنهان‌زدا" ایمن بنویسه.

هدف ساده بود: جایگزین کردن خطرناک `exec()` با یک `print()` که بار‌گذاری پنهان رو به عنوان متن ساده بیرون بریزه بدون اینکه واقعاً اجرا بشه.

اینجا اسکریپتی که ما استفاده کردیم برای غیرفعال کردن و استخراج بار‌گذاری:

```python
import base64
import zlib

key = 134
# رشته‌ی بزرگ اینجا می‌ره
payload_base64 = 'eNq9W19z3MaRTy...' 

# بیرون کشیدن لایه‌ها
decompressed_data = zlib.decompress(base64.b64decode(payload_base64))
decoded_bytes = bytes([b ^ key for b in decompressed_data])
hidden_script = decoded_bytes.decode('utf-8')

print("--------------------------------------------------")
print("🚨 بار‌گذاری پنهان اینه: 🚨\n")
print(hidden_script)
print("\n--------------------------------------------------")
```

## هیولای درون

اجرای رمزگشای رو در یک محیط آزمایش‌ای نشون داد ماهیت واقعی هیولا. اسکریپت Python نتیجه‌ای یک **Dropper/Loader** بسیار پیچیده بود که برای دزدیدن اطلاعات طراحی‌شده بود.

*(توجه: بار‌گذاری رمزگشایی‌شده‌ی کامل بسیار بزرگه، اما اینجا ویژگی‌های اصلی و وحشتناک که داخل داشت):*

1. **فرمان و کنترل Blockchain (C2):** به جای اتصال به یک آدرس IP سنتی و راحت‌تر قطع‌شدنی، بدافزار **Solana blockchain** رو پرس‌بجو می‌کنه. سابقه تراکنش‌های یک کیف‌پول خاص رو جستجو می‌کنه و دستورات رمزی‌شده پنهان‌شده در "Memos" تراکنش‌ها رو استخراج می‌کنه. این کار هم‌قریب غیرممکن می‌کنه زیرساخت‌های مهاجم رو از کار بیندازی.
2. **Geofencing (استثنای روسی):** اسکریپت یک تابع داره به نام `_isRussianSystem()`. زبان، منطقه‌ی زمانی، و محلی‌سازی سیستم رو بررسی می‌کنه. اگر ماشین آلوده در روسیه یا کشورهای CIS واقع باشه، بدافزار خاموشی خارج می‌شه. این تکتیک کلاسیک برای فرار از توجه مأموران پلیس محلی استفاده می‌شه.
3. **محیط خود بیاور:** بدافزار خاموشی سیستم عامل (Windows، macOS یا Linux) رو تشخیص می‌ده و نسخه‌ی قابل حمل **Node.js** رو مستقیم از سایت رسمی دانلود می‌کنه. بعد از این Node.js دانلود‌شده برای اجرای فایل JavaScript دوم و نامرئی‌ای (احتمالاً یک دزد مثل Lumma یا RedLine) استفاده می‌کنه تا رمزهای عبور، کوکی‌ها، و کیف‌پول‌های رمزارز رو بریزه بیرون.

## مقیاس آلودگی

با فکر کردن اینکه شاید یک اتفاق جداگانه باشه، من یک بخش از کد ته‌پنهان رو گرفتم و در تمام GitHub براش جستجو کردم.

نتایج جو‌انگیز بودند. **بیش از 300 مخزن با این کد دقیق‌تر آلوده‌شدند.** بعد از کمی تحقیق، به نظر می‌رسه این کد بدافزاری مستقیم‌تر در فایل‌ها در حین فرآیند `git commit` تزریق می‌شه. اگرچه بردار اولیه دقیق (چه یک افزونه VS Code سازش‌یافته باشه، یک بسته‌ی npm/PyPI بدافزاری، یا یک ابزار ترمینال قاچاق‌شده) هنوز راز دیگه‌یاشی هست که من براش تحقیق می‌کنم، نتیجه واضح: برنامه‌نویسان به‌ناخودآگاه بدافزار رو به مخازن خودشون‌شون می‌فرستند.

## خطر واقعی: مدل‌های ذهنی مسموم

اما اینجای چیزی هست که مرو بیدار نگه می‌داره: **داده‌های آموزش هوش‌مصنوعی.**

هزاران مهندس یادگیری ماشینی و محقق هوش‌مصنوعی فعالانه مخازن GitHub رو می‌خریند تا مدل‌های بزرگ زبانی (LLM)، مدل‌های تولید کد، و ابزار‌های تحلیل امنیتی خودشون رو آموزش بدند. اون‌ها کد منبع باز رو "داده‌های آموزش رایگان" درمی‌اندیشند. چیزی که نمی‌فهمند اینه که احتمالاً این قطعه‌های بدافزاری و ته‌پنهان‌شده رو جاروب می‌کنند و مستقیم وارد شبکه‌های عصبی‌شون می‌کنند.

یک سناریوی فرضی تصور کن که یک مدل هوش‌مصنوعی روی 300+ مخزن آلوده آموزش دیده باشه. کد بدافزار، عمیق درون هزاران نمونه کد قانونی، بخشی از الگوهای یادگرفته‌ی مدل می‌شه. جلو رفتن به تولید: برنامه‌نویسان از این مدل "آموزش‌دیده" استفاده می‌کنند تا:
- پیشنهاد کد تولید کنند (و مدل بدافزار ته‌پنهان پیشنهاد می‌ده)
- آسیب‌پذیری‌های امنیتی تحلیل کنند (اما خود مدل درگیری‌های پنهان‌شده داره)
- وابستگی‌های شخص ثالث تایید کنند (درحالی‌که ناخودآگاه بسته‌های سازش‌یافته‌ی پیشنهاد می‌دهند)

کابوس واقعی فقط یک مدل مسموم نیست—یک غیرقابل تشخیص. بدافزار درون وزنه‌های ریاضی و تعصب‌های شبکه عصبی زندگی می‌کنه، برای هر تحلیل کد ثابت نامرئی. آن‌ها صندوق‌های شنی یا اسکنرهای ضدویروس رو فعال نمی‌کند چون کد "در حال اجرا" نیست؛ رفتار یادگرفته‌ای درون هست. تا زمانی که مدل شروع به تولید پیشنهاد‌های بدافزاری در تولید نکنه هرگز نمی‌تونی اون رو پیدا کنی، احتمالاً به‌طور مقررات هزاران پروژه دنباله‌ای رو آسیب‌دهی.

این یک حمله‌ی زنجیره تامین هست که از مخازن فراتر می‌رود و ابزار‌های بسیار که ما برای نوشتن کد ایمن استفاده می‌کنیم رو مسموم می‌کند.

## کاهش خطر: یک همپالایی سریع

تا اینکه دقیق شناسایی کنیم کدوم ابزار یا بسته‌ای فرآیند commit رو قاچاق می‌کنه، ما نیاز‌ داریم یک راه برای متوقف کردن خونریزی.

چون این بدافزار به تزریق یک رشته‌ی base64 بزرگ و پیوسته‌ای در کد متکی برای پیلوید، ساده‌ترین راه برای جلوگیری از آلوده‌شدن مخزنت (و پخش کردنش به دیگران) این است که یک **Pre-commit Hook** سخت‌قانون‌ی راه‌اندازی کنی.

می‌تونی هر commit رو منع کنی که حاوی رشته‌ی غیرطبیعی طولانی باشه (مثلاً بیش از 100 کاراکتر بدون فاصله). اینجا مفهوم ساده‌‌ای برای یک hook pre-commit گیت که می‌تونی به فایل `.git/hooks/pre-commit` اضافه کنی:

```bash
#!/bin/bash
# یک hook pre-commit ساده برای گرفتن تزریق‌های base64 بزرگ

if git diff --cached | grep -E '[a-zA-Z0-9+/]{100,}'; then
    echo "🚨 هشدار امنیتی: رشته‌ی مریب طولانی (بار‌گذاری Base64 احتمالی) تشخیص داده‌شد."
    echo "Commit رد‌شد. لطفاً کد‌تون رو برای بدافزار تزریق‌شده بررسی کن."
    exit 1
fi
```
