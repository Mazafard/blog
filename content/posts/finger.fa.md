خیلی پیش از الگوریتم‌ها، معیارهای تعامل و اعلان‌های بی‌پایان، اینترنت راهی فوق‌العاده ساده برای دیدن وضعیت دیگران داشت: Finger.

این پروتکل در سال ۱۹۷۱ در دانشگاه استنفورد شکل گرفت و بعدها در RFC 742 و سپس RFC 1288 استاندارد شد. Finger یک پروتکل مینیمال و متنی است که روی پورت ۷۹ TCP اجرا می‌شود. وقتی با دستور `finger user@host` یک کاربر رو بررسی می‌کنید، ماشین مقصد اطلاعات پایه‌ای درباره اون رو به‌همراه محتوای یک فایل متنی ساده به نام `.plan` برمی‌گرداند.

برنامه‌نویسان بزرگی مثل جان کارمک در دهه ۱۹۹۰ از فایل‌های `.plan` خود به‌عنوان یک لاگ توسعه شفاف و خام استفاده می‌کردند. اگر از IndieWeb، پروتکل‌های غیرمتمرکز یا مینیمالیسم ساده‌ی یونیکس لذت می‌برید، راه‌اندازی یک حضور Finger برای خودتان پروژه‌ای سرگرم‌کننده و کوتاه است که فقط در چند دقیقه انجام می‌شود.

## روش اول: راه‌اندازی بدون سرور (Happy Net Box)

اگر نمی‌خواهید سرور مدیریت کنید یا پورت فایروال باز کنید، سرویس‌هایی مثل `happynetbox.com` یک رابط وب ساده ارائه می‌دهند که به شبکه Finger متصل می‌شود.

1. یک حساب رایگان در `happynetbox.com` بسازید.
2. وضعیت متنی، ASCII art یا گزارش روزانه‌تون رو در ویرایشگر مرورگر وارد کنید.
3. تغییرات رو ذخیره کنید.

حالا هر کسی در دنیا می‌تونه وضعیت شما رو مستقیمن از ترمینال خودش بررسی کنه:

```bash
finger mazafard@happynetbox.com
```

## روش دوم: میزبانی روی سرور ابونتوی شخصی

اگر یک سرور Ubuntu دارید (VPS، سرور ابری یا سرور خانگی)، می‌توانید یک سرویس Finger بومی و امن اجرا کنید.

### گام ۱: نصب `openbsd-inetd` و `ffingerd`

نسخه قدیمی `fingerd` در دهه ۱۹۸۰ مشکلات امنیتی داشت. روی توزیع‌های مدرن Debian/Ubuntu از `ffingerd` استفاده می‌شه؛ یک جایگزین امن و سازگار که مخصوص سرورهای عمومی طراحی شده .

```bash
sudo apt update
sudo apt install openbsd-inetd ffingerd finger -y
```

### گام ۲: تنظیم Super-Server

فایل پیکربندی super-server رو باز کنید:

```bash
sudo nano /etc/inetd.conf
```

مطمئن شوید خط زیر وجود دارد (یا خط فعلی `finger` رو با آن جایگزین کنید):

```text
finger stream tcp nowait nobody /usr/sbin/tcpd /usr/sbin/ffingerd
```

تغییرات رو ذخیره کنید (`Ctrl+O`, `Enter`, `Ctrl+X`) و سپس سرویس رو دوباره راه‌اندازی کنید:

```bash
sudo systemctl restart openbsd-inetd
```

### گام ۳: ساخت فایل `.plan`

یک فایل `.plan` در دایرکتوری خانه‌ی کاربر خود بسازید و دسترسی خوندن عمومی به اون بدید تا کاربر `nobody` بتواند اون رو سرو کنه:

```bash
cat <<'EOF' > ~/.plan
======================================================
  mazafard's terminal space
======================================================

--- 2026-08-19 ---
Serving plain text over port 79.
Minimalism over algorithms.

* Blog: https://blog.fard.pt
* X   : https://x.com/mazafard
EOF

chmod 644 ~/.plan
```

### گام ۴: باز کردن پورت ۷۹ در فایروال

Finger روی پورت TCP ۷۹ کار می‌کند. ترافیک رو در UFW مجاز کنید:

```bash
sudo ufw allow 79/tcp
sudo ufw reload
```

> اگر سرور شما روی یک سرویس ابری مثل Hetzner، AWS یا DigitalOcean است، مطمئن شوید که پورت TCP ۷۹ در گروه امنیتی یا فایروال ابری هم بازه.

### گام ۵: تست تنظیمات

از لپ‌تاپ یا ترمینال دیگری، این دستور رو اجرا کنید:

```bash
finger yourusername@your-server-ip
```

اگر یک رکورد DNS A استاندارد (مثلاً `finger.yourdomain.com`) به IP سرور شما اشاره کنه، می‌تونید از طریق دامنه هم آن رو تست کنید:

```bash
finger yourusername@finger.yourdomain.com
```

## چرا امروز هم Finger رو استفاده کنیم؟

Finger سعی نداره جای ارتباطات مدرن رو بگیره. این یک artifact از تاریخ کامپیوتر است که هنوز کاملن عملیه: متنی، مالک خود، بدون ردیابی و کاملن مستقیم.

این ترکیب سخته که نادیده گرفته شه. Finger یک پروتکل کوچک و صادق است که یادآور می‌شود اینترنت روزگاری شخصی‌تر، محلی‌تر و کمتر متمرکز بر جذب توجه بود.

اگر به دنبال یک پروژه کوچک و خاص‌اید که هیجان زیادی هم داشته باشد، Finger یکی از بهترین راه‌ها برای بازگردوندن کمی از آن اینترنت قدیمی به دنیای امروزه.
